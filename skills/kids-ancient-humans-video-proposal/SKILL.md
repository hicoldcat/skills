# 儿童科普短视频选题与脚本生成器

## 这个 Skill 做什么

围绕一个主题（默认 **古代人类 / Ancient Humans**），一次性产出 **恰好 10 个**儿童科普短视频选题，
每个选题包含中英标题、核心知识点、英文旁白（60–70 词为**参考区间**，非硬性）+ 中文译文、
双语社媒贴文、双语话题标签、儿童吸引力分析。

最终产物是**一个真实的 `.md` 文件**（不是聊天窗口里的长文本），并通过
`scripts/validate_script_doc.py` 校验后才能交付 —— 且**必须给出可点击的访问/下载链接**。

- 与儿童科普无关的一般文案写作。

判断模糊时：只要用户明确要"**一批（≈10 个）儿童科普短视频选题 + 完整中英内容**"，就走本 Skill。

## 执行逻辑（按顺序执行，不可跳步）

### Step 0 — 加载规范
读取 `references/content-spec.md`（完整创作规范，硬性规则的权威来源）与
`references/output-template.md`（Markdown 输出骨架）。二者是执行依据，不得凭记忆简化。

### Step 1 — 锁定参数
1. 确定 `主题`、`ZH_KEYWORD`、`EN_KEYWORD`、`输出目录`。
   同时判断用户有没有点名子主题：有 → 记下 `USER_TOPIC` 原文并提炼 `TOPIC_ANCHORS`（见 Step 2 模式 B）。
2. **用 shell 取真实时间戳**，禁止自行推算：

   ```bash
   date +%Y%m%d%H%M%S
   ```

3. 拼出文件名：`{主题}-{YYYYMMDDHHmmss}.md`
   例：`古代人类-20261014213045.md`（**不含平台名**）
4. 先用带时间戳的临时路径暂存，校验全部通过后即为最终文件（文件名不含临时后缀）。

### Step 2 — 构思 10 个选题

恰好 10 个，不多不少。**先判断走哪种模式**（这一步判错，后面全错）：

#### 模式 A — 用户没给子主题（`USER_TOPIC` 为空，自由发散）

- **多样性是硬约束**：10 个选题必须覆盖不同生活场景/行为/工具/科学现象，不得集中在同一场景或重复讲相似知识。
- 每个选题同时产出中文标题（含 `ZH_KEYWORD` 连续串）与英文标题（含 `EN_KEYWORD` 连续串）。
- 标题按《选题钩子（"梗"）要求》写，不得夸大或误导。

#### 模式 B — 用户给了子主题（`USER_TOPIC` 非空，收敛模式）

用户那句话是这一包的**母题**，不是"参考灵感"。典型问法："以『没有空调古人是如何过夏』作为主题生成选题"。

1. **提炼锚词**：从用户原话抽出 2–4 个锚词写进 `TOPIC_ANCHORS`，**同义说法一并列出**（供校验脚本比对）。
   例：「没有空调古人是如何过夏」→ `夏天 / 暑 / 炎热 / 降温 / 避暑`。
2. **选题 1 必须直给**：
   - 标题就是用户那个问题，可以用钩子句式重写，但**不许换题、不许把它拆成更小的子问题**；
   - 核心知识点必须**正面回答**它，第一条补充事实也必须贴着它；
   - 旁白从第一句起就在讲这件事，不许用"先说说古人怎么生火"这类铺垫绕开。
3. **选题 2–10 必须在同一主题簇内展开**，每条都要能**一句话**说清"它和用户主题是什么关系"。可选角度（逐条换着用，别重复）：

   | 角度 | 说明 | 「过夏」为例 |
   |---|---|---|
   | 机制 / 原因 | 为什么会这样 | 为什么山洞里比外面凉 |
   | 器物 / 工具 | 用了什么 | 扇子、草席、水罐 |
   | 空间 / 居住 | 住哪、怎么布置 | 半地穴房屋、通风口 |
   | 身体 / 衣物 | 身体怎么应对 | 少穿、涂泥、泡水 |
   | 饮食 / 水 | 吃什么喝什么 | 储水、避暑食物 |
   | 作息 / 时间 | 什么时候干活 | 早晚活动、午间躲避 |
   | 儿童视角 | 孩子怎么过 | 古代小孩的夏天 |
   | 反常识纠错 | 常见误解是错的 | "古人夏天并不都穿得少" |
   | 古今对照 | 和今天比 | 没有冰箱怎么存食物 |
   | 代价 / 副作用 | 这么做要付什么代价 | 凉快了，但蚊虫和烟熏也更凶 |

4. **禁止跨域**：不得出现与用户子主题无关的古代生活场景。
   「过夏」的包里不该有"狩猎猛犸""洞穴壁画""发明文字"这类题。
5. **发散半径自检**（写完必做，不许跳）：逐条问"这条单独发出去，观众能不能一眼看出它属于『{USER_TOPIC}』这个系列？"
   答不上来的换掉；再把 10 条按"离母题的距离"排一遍，最远的那条如果需要额外解释才能连上，删掉重写。

> 两种模式**标题关键词规则不变**：`ZH_KEYWORD` / `EN_KEYWORD` 仍必须连续出现在每个标题里。
> 用户给的是**子主题**，不改变 `ZH_KEYWORD`（除非用户明确要求换关键词）。

#### 通用要求
- 10 条标题的钩子类型不能全一样（见《选题钩子（"梗"）要求》）。
- 落笔前先用一行一条列清 10 个选题（编号 → 角度 → 钩子类型），确认既不同质也不跑偏，再展开写正文。

### Step 3 — 逐个选题写完整内容
严格按 `references/output-template.md` 的字段顺序填充。除「单词数量（参考）」为**可选**外，
其余字段**一个都不能缺、不能省**：

1. 中文标题 / English Title
2. 核心知识点（主知识点 + 1–3 条补充事实 + 必要的不确定性说明）
3. 英文旁白（正文）—— 60–70 词只是**参考区间**；够讲清就短、需要才长，不牺牲自然度
4. `**单词数量（参考）：** XX words` —— **可选**。写了就必须用脚本实测，标注与实测不一致会 FAIL
5. 中文旁白（对应英文旁白的完整中文翻译，不逐词直译）
6. 中文贴文（抖音 / 小红书，30–80 汉字）
7. English Post (X / YouTube Shorts，20–50 词)
8. 中文话题标签（5–8 个）
9. 英文话题标签（3–6 个）
10. 儿童吸引力分析（一句话，写明**用了哪类钩子 + 为什么对孩子有效**）

**不要为了凑字数而重复内容、堆砌形容词或塞无关信息。**

### Step 4 — 写入 Markdown 文件
- UTF-8 编码，标准 Markdown 语法。
- 文档结构：`第一部分：10 个选题总览（表格）` → `第二部分：10 个选题完整内容`。
  **只此两个部分** —— 质量检查清单属执行者自检，**不写入交付文档**。
- 禁止"此处省略""其余选题类似"——10 个选题全部写满。

### Step 5 — 运行校验（门槛）
```bash
# 模式 A（用户没给子主题）
python "<SKILL_DIR>/scripts/validate_script_doc.py" "<生成的.md路径>" \
  --zh-keyword "<ZH_KEYWORD>" --en-keyword "<EN_KEYWORD>" --min 60 --max 70

# 模式 B（用户给了子主题）：上面这条再追加一行
#   --topic-anchor "夏天,暑,炎热,降温,避暑"
```

> 用户给了子主题（模式 B）时**必须**带 `--topic-anchor`（逗号分隔的锚词），否则"选题 1 是否直给"没人把关。

脚本输出三级结论：

- **PASS** — 合格
- **WARN** — 参考提示，**不阻断交付**。主要是英文旁白词数超出 60–70 参考区间、文档里多写了「第三部分」、
  或（模式 B）选题 2–10 中有没命中主题锚词的，提示"可能发散过远"
- **FAIL** — 必须修复

FAIL 覆盖：文件名格式、选题数=10、标题关键词连续出现、必备字段齐全、
词数标注与实测不一致、中文贴文汉字数、英文贴文词数、中英标签数量、总览表 10 行、
**选题 1 未命中任何主题锚词**（仅当传了 `--topic-anchor`）。

### Step 6 — 有 FAIL 就修，修完重跑
**只要脚本报 FAIL，就必须修改内容并重新运行脚本，直到没有 FAIL。**
不得因为"看起来差不多"就跳过，也不得手动改标注数字来骗过校验（脚本以实测值为准）。
WARN 项需在完成说明里如实提及，但不必强行消除。

> 如需恢复旧版「60–70 词硬性卡口」行为，加 `--strict-words` 参数即可把词数越界升级为 FAIL。

### Step 7 — 交付
1. **必须**用 `present_files` 展示生成的 `.md` 文件，提供可点击的访问/下载链接。
   原任务书允许"不落盘、不提供链接"，**本 Skill 不采用该宽松条款**。
2. 聊天窗口给出简短完成说明：选题数量、**如果用户给了子主题，明确说出选题 1 是哪个题、以及 10 条各自的角度**、
   词数校验结论（含 WARN 项）、文件名。

## 选题钩子（"梗"）要求

这套内容是给自媒体（抖音 / 小红书 / YouTube Shorts）发的，**标题必须自带钩子**，不能写成教科书目录。

### 1. 每条至少用 1 类钩子，10 条不许全用同一类

| 钩子类型 | 做法 | 例（主题=过夏） |
|---|---|---|
| 古今对照 | 拿现代物件当参照物 | 古代人类没有空调，夏天靠什么降温？ |
| 反常识 | 先立一个"大家都以为"的认知，再推翻 | 古代人类夏天其实穿得不少？ |
| 算账 | 用具体数字造画面 | 古代人类为了打水，一天要走多远？ |
| 代价 | 讲"凉快要付出什么" | 古代人类避暑的代价：凉快了，蚊子更多 |
| 身份反差 | 把古人当邻居 / 同学 / 亲戚 | 如果古代人类来你家过暑假 |
| 未解 | 留一个连科学家也没完全弄明白的悬念 | 古代人类造的"空调房"，到底怎么通风的？ |
| 画面 / 拟声 | 有声音、有动作、能演出来 | 古代人类夏天的声音：蛙叫、水声、扇风声 |

### 2. 标题写法

- **钩子放前 6–10 个字**，别压到句尾。
- 最稳的起手式：「现代参照物 + 反差疑问」——"没有 X 的古代人类，怎么 Y？"
- 允许口语、允许一点调侃、可以带一个 emoji；但**标题承诺的东西旁白必须兑现**。

### 3. 禁用（违反即返工）

- 空转夸张："震惊""太可怕了""99% 的人不知道""史上最""看完跪了"。
- 无依据的悬念："科学家都不敢说的真相"。
- 拿恐惧、血腥、死亡当钩子（儿童向底线）。
- 标题里的知识点与旁白对不上（标题党）。

### 4. 落到字段上

`**儿童吸引力分析：**` 必须写明**用了哪类钩子 + 为什么对孩子有效**，例如
"用『没有空调』这个孩子有体感的现代物件做古今对照，孩子会立刻想知道替代方案"。
不许写"这个故事非常有趣"这类空话。

## 科学准确性红线

1. 不编造考古发现、年代、实验结论或科学家观点；证据不足时用"可能""研究表明""科学家认为"。
2. 明确区分**史前人类 / 石器时代人群 / 古代文明人群**，不混为一谈。
3. 不假设所有古人类都住洞穴、穿兽皮、用同样工具——尊重气候、环境、时代与文化差异。
4. 不把猜测当已证实事实，不为戏剧性牺牲准确性。
5. 标题前提有误时，旁白要**友好地纠正**，而不是顺着错误前提讲下去。
6. 适合儿童观看：避免血腥、恐怖、残酷或过度刺激的细节。
7. 不把古人饮食/生活习惯包装成现代健康建议。
